## 1. 背景と課題

家計簿アプリは「つけ始めても続かない」ことが最大の課題。既存アプリの多くは入力と集計が中心で、記録を続ける動機が弱い。特に衝動買い・散財癖のある人ほど、支出の記録は「怒られている」感覚になり離脱しやすい。

## 2. プロダクトの狙い

**カワウソのマスコットが支出に反応し、実績バッジで記録の継続を報いることで、家計簿を「続けられる習慣」にする。**

- 記録すること自体が楽しい（カワウソのリアクション・実績解除）
- 叱るのではなく励ます（節約できたら喜び、使いすぎたら心配する）
- 一人で続けにくい人は掲示板で仲間と節約のコツを共有できる

## 3. ターゲットユーザー

| ペルソナ | 特徴 | 主なニーズ |
|---|---|---|
| 散財しがちな20〜30代 | 衝動買いが多く、月末に残高が足りなくなる | 使いすぎに早く気づきたい。重くない記録体験 |
| 家計簿挫折経験者 | 何度もアプリを入れては放置してきた | 続ける理由・小さな達成感 |
| 貯金目標がある人 | 旅行・引っ越し等の目標額がある | 目標までの進捗が見える |

## 4. 主要ユーザーストーリー

1. ユーザーとして、収入・支出を数秒で記録したい。家計の流れを把握するため。
2. ユーザーとして、カテゴリ別・月別の支出をグラフで見たい。使いすぎの傾向を知るため。
3. ユーザーとして、月の予算を設定し残りを把握したい。月末に困らないため。
4. ユーザーとして、貯金目標を立て進捗を見たい。目標を意識し続けるため。
5. ユーザーとして、行動に応じて実績バッジを獲得したい。続ける達成感を得るため。
6. ユーザーとして、カワウソが自分の家計状況に反応してほしい。記録が楽しくなるため。
7. ユーザーとして、節約のコツを投稿・閲覧・いいね・ブックマークしたい。仲間と励まし合うため。
8. 未登録ユーザーとして、ゲストで試したい。登録前に価値を確かめるため。

## 6. 非機能要件

| 分類 | 要件 |
|---|---|
| セキュリティ | 家計データは本人のみ参照可（全クエリを `current_user` でスコープ）。アクセストークン 30 分・リフレッシュトークン 14 日（ローテーション）。ログイン・登録・リセット・問い合わせにレート制限。メールアドレス・トークン等をログに残さない（詳細は `.claude/rules/security.md`） |
| 性能 | 主要画面の初回表示 3 秒以内（コールドスタート時を除く）。API の p95 500ms 以内 |
| 可用性 | 個人開発のベストエフォート。無料プランのスリープによる初回遅延は許容するが、UI でローディングを明示する |
| 対応環境 | モバイルファースト。最新の Chrome / Safari / Edge / Firefox |
| アクセシビリティ | コントラスト比 WCAG AA、キーボード操作可能、色だけで収入/支出を区別しない |
| 言語 | 日本語のみ（UI・エラーメッセージ） |
| 品質 | CI で RuboCop / Brakeman / RSpec / ESLint / TypeCheck / Jest / build が全て通ること |

## 7. 成功指標

| 指標 | 定義 | 目標（初期値） |
|---|---|---|
| 7日継続率 | 登録後 7 日目に取引を 1 件以上記録したユーザー割合 | 30% |
| 週あたり記録日数 | アクティブユーザーが取引を記録した日数/週 | 3 日 |
| 実績解除数 | 登録 30 日以内に解除した実績の平均数 | 5 個 |
| ゲスト→登録転換率 | ゲストログイン後に本登録したセッション割合 | 10% |

> 現状は計測基盤がない。まずはサーバーログ・DB 集計で算出し、必要になったら分析ツールを検討する。

## 8. スコープ外（やらないこと）

- 銀行口座・クレジットカードとの自動連携（セキュリティ・規約の負担が大きい）
- 複数通貨・多言語対応
- 家族・複数人での家計共有
- ネイティブアプリ（まずは Web のモバイル対応で検証する）
- 投資・資産運用の助言

## 9. 既知の課題・未決事項

- **ゲストログインが単一の共有アカウント**（`guest@otter-bank.example.com`）。複数のゲストが同じ家計データを見る・書き換える。ゲストごとに一時ユーザーを作り、一定期間後に削除する方式を検討する
- **本番 API のコールドスタート**（Render 無料プラン）。初回アクセスが数十秒かかり、ゲーミフィケーションの「気持ちよさ」を損なう
- 掲示板のモデレーション（通報・非表示）がない
- 成功指標を計測する仕組みがない
